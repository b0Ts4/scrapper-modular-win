# Event engine

**Triggers.** `UiAutomationTriggerProvider` resolves a trigger's element, subscribes to `InvokePattern.InvokedEvent`, raises `WatchEstablished` once the subscription is live, and yields a `TriggerSignal` (session, trigger ID, time, native occurrence ID — never a value) per invoke. A liveness poll ends the watch with a typed `ElementInspectionFailure` if the element disappears. `TriggerDeduplicator` collapses signals for the same session and trigger within 500 ms (double click / duplicated UIA event).

**Sessions.** `AgentRuntime` watches `IApplicationInstanceSource` and creates one `SessionCoordinator` per process instance; sessions never share state or sequences. The coordinator serializes occurrences per session, captures fields, applies the immutable `SessionEngine` (see [session contract](../sessions.md)), appends emitted events to the outbox **before** publishing `EventPersisted`, and publishes typed `RuntimeDiagnostic`s: `TriggerWatchStarted`, `TriggerWatchFailed`, `EventPersisted`, `SessionRejected`, `SessionIgnored`, `SelectorFallback`, `SessionClosed`. Application close ends the session without an event. A trigger watch that fails (element not on screen yet, or gone) is reported once per failure streak as `TriggerWatchFailed` and retried every 2 s until it recovers (`TriggerWatchStarted` again) or the session ends.

**Activation gate.** `ConfigurationFingerprint.Compute` hashes the configuration's content. A passing `IntegrationTestReport` produces a `ConfigurationApproval` bound to that hash; `ActivateAsync` returns `NotTested` without watching anything when the approval is missing or the configuration changed since it was tested. Approvals are persisted by `JsonApprovalStore` (`approvals/<id>.approval.json`: configuration ID, content hash, time — no captured value); `ApprovalService` reports `NotTested`, `Approved` or `ChangedSinceTest` for the current content and only `Approved` yields an approval for the gate. An unreadable or foreign approval file never approves anything. A tested configuration therefore activates after an Agent restart, while any edit (until undone) requires a new test.

**Events.** `DomainEvent` carries ID, configuration ID, schema version and **content revision** (`ConfigurationRevision` = the same SHA-256 content hash approvals are bound to, so each event names the exact configuration that produced it), session ID, per-session sequence, timestamp, type (`item_added`, `budget_finished`, custom) and a payload of fields plus confirmed items. `item_added` appends a confirmed item; `FinishSessionAction` emits `budget_finished` with every confirmed item and ends the session. No event is emitted while a required field (of any stage) is missing.

**Outbox.** `SqliteEventOutbox` stores metadata in queryable columns and the serialized payload as DPAPI ciphertext, appends transactionally and idempotently by event ID (schema v2 adds the nullable `configuration_revision` column; a v1 queue is migrated in place keeping its events), reads pending events in append order, quarantines undecryptable payloads, and deletes only confirmed events older than the retention window. `OutboxCapacityPolicy` reports warning/critical pressure without deleting pending events.

**Integration health.** `IntegrationHealthTracker` (Application) derives `Healthy` / `Degraded` / `Broken` from the diagnostics: a trigger that cannot be watched, or a field that cannot be read when its trigger fires, makes the integration Broken; a low-confidence match makes it Degraded. Each issue clears when its trigger is watched again or persists an event with the field captured cleanly. An operator leaving a required field empty is not a configuration problem. The Desktop monitor shows the state with its reasons (field/trigger IDs and confidence only).

**Transient failures.** When a trigger fires, a field that is momentarily unavailable (window or element not found yet, resolution or read timed out, element unavailable or covered) is retried by `CaptureRetryPolicy`: at most 3 attempts, 100 ms then 200 ms apart, cancellable, each re-running the full selector resolution (`field_capture_retried` in the technical log, no value). Ambiguity, unsupported controls and files that are too large or missing are never retried. The wait is short on purpose: the application may change its screen right after the click.

**Stopping.** Cancelling the activation token is how monitoring stops; `ActivateAsync` then closes every session and returns normally, whatever point of the instance poll the cancellation reached.

**Start with Windows.** The Desktop's *Iniciar com o Windows* option writes `"<exe>" --background` to the current user's `Run` key (`RunKeyStartupRegistration`; per user, no administrator rights; the user's interactive session is required by UI Automation and DPAPI, so a Windows service is not used). In background mode the window stays hidden behind a tray icon and `StartupActivation` resumes only the integration the operator left active (`monitoring.json`, written on Activate, cleared by Stop; exiting keeps it) and only while its approval matches its content; otherwise the reason is shown in a tray notification and the status line. One Agent runs per data directory (named mutex): a second start shows the running window and exits, so an application is never monitored twice.
