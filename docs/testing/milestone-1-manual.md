## Real Windows applications on the CI runner

`scripts/probe-real-apps.ps1` runs on every CI build and prints what the runner (`windows-latest` = Windows Server 2025) has. Observed on 2026-10-06:

- `calc.exe` opens the **classic calculator** (`win32calc`, title "Calculator", Win32 control IDs as AutomationIds: digits `130`–`139`, `=` `121`, display `150`). The Store Calculator (`CalculatorApp`) is **not installed**, so tests that need it skip with that reason.
- `notepad.exe` is the **classic Notepad** (title "Untitled - Notepad", text area AutomationId `15`).
- `mspaint.exe` exists; Paint has no tests (its canvas is a drawing surface, see below).

Real-app tests use AutomationIds only (never names, which change with the language), close the processes they start, and skip with an explicit reason when the application is missing.

## Known limitations of UI Automation capture

- **Electron / Chromium apps** (and browsers): content is exposed only when the app enables its accessibility tree; otherwise elements are generic and without AutomationIds — prefer the label (structural) selector or OCR.
- **Java (Swing/AWT)** apps: need the Java Access Bridge enabled on the machine; without it the window is one opaque element.
- **Canvas / drawn content** (Paint's canvas, games, charts, some legacy grids): there is no element to read — use a *Texto via OCR* field over that area.
- **Plain labels** with no pattern (a calculator display, an ERP total) are read through their name (fixed 2026-10-06).
- **Window titles that change** (Notepad's "Untitled - Notepad" becomes the file name) must match the integration's window title; such programs need the title as it will be when the integration runs.
